# 收集器说明

收集器（`collector` 包）面向授权的学习记录库，把学生真实参与的原始证据——xAPI
语句原文、随附或授权下载的二进制材料、以及后来的作废语句——一起留存并可追溯，
同时给出不含已作废活动的有效参与视图。所有数据均为合成记录。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `collector/client.py` | 只读来源客户端：按 stored 翻页、跟随 more 不改查询、解析 multipart/mixed、按 fileUrl 下载材料、按 voidedStatementId 取回已作废原文 |
| `collector/store.py` | 本地证据库：SQLite 关系数据 + 按 sha2 内容寻址的字节存储与隔离区 |
| `collector/collect.py` | 一轮轮收集的编排：水位推进、附件收纳/补下载、作废引用闭合、中断标记 |
| `collector/views.py` | 解释视图：每条语句的有效性、材料完整性、未闭合引用、有效参与证据 |
| `collector/cli.py` | 命令行：`collect` / `status` / `evidence` / `show` |

## 收齐范围与接续（stored，而非事件时间）

- 活动发生时间 `timestamp` 可能早于入库时间 `stored` 很多天；连续读取只依据
  `stored`，查询参数为 `since`（stored 严格大于）。
- 稳定可见边界只信任响应头 `X-Experience-API-Consistent-Through`。一轮收集把本
  查询所有 `more` 页翻完后，取**各页边界的最小值**作为本轮确认值写入本地水位；
  任一来源异常都会中断本轮且**不推进水位**，下次仍从旧 `since` 接续。
- `more` 只表示当前查询的后续页，不表示较早发生的活动已收齐。stored 晚于确认边
  界的语句照样留存，并在收集报告中列入 `beyond_boundary`，下一轮再次读到时由语
  句 id 幂等去重。因此“本次确认收齐的入库范围”始终明确表达为
  `stored <= <consistent-through>`，晚到的旧活动入库后能无缝接续进入。
- 水位与每轮运行记录保存在 SQLite 的 `kv` 与 `runs` 表，中断后的运行标记为
  `interrupted` 并附原因，不能用最终条数掩盖漏页或漏附件。

## 语句身份与跨项目参与

- 语句 id 是不可变身份，按 id 幂等 upsert，原文 `raw_json` 不被后续覆盖。
- 学生跨项目参与时，同一个活动对象（相同 activity id）不等于同一次参与。视图按
  语句逐条成行，结合 `context.contextActivities.grouping` 的项目标识区分，**不
  按时间或活动名称合并语句**。

## 作废语义（单向，不恢复）

- voided 动词的作废语句通过 StatementRef 指向目标，允许目标原文尚未到达：先登记
  作废关系，`resolved=0` 作为“未闭合引用”显式展示。
- 目标原文后到时，普通 `statementId` 查询不返回已作废语句；收集器改用
  `voidedStatementId` 通道取回原文并立即保持其作废状态。**稍后补到原文不会让
  活动恢复有效**。
- 附件缺失后补齐只改变材料完整性，不撤销作废。被作废语句的原文始终可通过
  `show` 追溯。

## 附件与字节存储

- `attachments=true` 的 multipart/mixed 响应：首部分 JSON，其后二进制部分按
  `X-Experience-API-Hash`（sha2）关联；同一摘要一份响应只随附一次。没有随附的，
  按语句自己的 `fileUrl` 授权下载；材料发布前的 503 记为可恢复缺口（`pending`），
  不判为永久失败。
- 磁盘按内容寻址：`blobs/<sha2前2位>/<sha2>`。多个语句共用一个 sha2 时字节只落
  盘一次，但每条语句在 `attachment_refs` 各自保留独立引用行（自己的 fileUrl、
  length、contentType、来源文件名），**文件复用不会把一条语句的权限或来源凭据
  混给另一条**；授权令牌只在请求头使用，绝不写入证据库。
- 来源文件名不是身份，磁盘不按文件名存放，因此同名图片不会相互覆盖；来源文件名
  仅作为引用元数据保留。
- 落盘前同时校验 sha2 与声明 length：任一不符，字节写入 `quarantine/` 隔离区且
  不进入正式字节区，引用标记为 `corrupt`，依赖它的语句在合格字节补齐前保持材料
  不完整，不能交付为证据齐全。来源恢复后重跑可就同一引用补齐。

## 三个面向使用者的状态量

`status` 对每条语句给出：

1. **当前有效性**：活动语句为“有效”或“已作废·无效”；作废指令单独归类，不作为
   参与证据；
2. **材料完整性**：声明的每个附件都有核验通过的字节才算完整，`pending`/`corrupt`
   均算不完整；
3. **未闭合引用**：作废语句已到、被指向原文未到的 StatementRef 列表。

`evidence` 输出有效参与视图，仅包含“未作废且材料完整”的活动语句。

## 命令

    python -m collector.cli collect --base <来源基址> --repo <证据库目录> [--token T] [--json]
    python -m collector.cli status   --repo <证据库目录> [--json]
    python -m collector.cli evidence --repo <证据库目录> [--json]
    python -m collector.cli show <statement-uuid> --repo <证据库目录>

收集器只访问契约规定的资料端点（`/xapi/statements`、`/xapi/more`、`/files/...`），
不调用 `/__control` 演练控制接口。
